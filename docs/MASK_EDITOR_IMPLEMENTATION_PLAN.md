# Editable sky mask — implementation plan

Status: implemented in the Preview 0.2.0 source branch, 4 October 2026. This records the design and its acceptance checks. The calibration, solar-position, irradiance, transposition, shading-correction and PV/battery equations are unchanged.

## User workflow

1. Run **Update results** to generate the AI mask for the selected sky photo. The mask preview gets an **Edit mask** button at its lower corner. It is enabled only when the displayed full-resolution mask still matches the selected photo and no update is in progress.
2. The button opens a dedicated secondary **Mask Editor** window owned by the main window. It is resizable and keeps the main study controls unavailable until Save or Cancel. It shows the original photo and the binary mask in the same EXIF-oriented native-pixel coordinates. A **Mask opacity** slider stays visible while painting: 0% shows the photo, 100% shows the mask, and intermediate values show both. Painting always changes the binary mask regardless of this display setting. The sun-path and cardinal overlays are not paint layers.
3. Choose **Black — obstruction** or **White — open sky**, set brush diameter in original-image pixels, and paint. A visible **Zoom** slider (5–800%), numeric zoom value, **Fit image** action, cursor-anchored mouse-wheel zoom and right-drag pan make boundary work possible on a 3000 × 4000 photo. The opacity and zoom sliders can both be adjusted during a brush stroke session. A brush cursor, undo/redo and **Reset to opening mask** complete the editing controls. A continuous drag paints one stroke; interpolation fills gaps between pointer events. Undo stores bounded changed-pixel regions per stroke instead of copying the entire image each time. Pixels remain exactly 0 or 255, with no antialiasing in the saved mask.
4. **Save as new mask** proposes a local-time display name such as `Edited 04 Oct 2026 16:30` and allows a custom label. Its durable ID/filename uses UTC time plus a short random suffix, for example `mask-20261004T093012Z-a1b2c3`; collisions cannot overwrite a mask. Saving a revision of an edited mask creates another variant. **Cancel** leaves the current selection and calculation untouched; closing with unsaved strokes asks whether to discard them.
5. A **Mask for calculation** dropdown below the mask preview lists `AI mask (current model)` and compatible saved variants, with their label, save time and base model. A new save is selected automatically. The app remembers the last selected mask for each photo. Selecting a mask or returning to a known photo updates the preview from its saved mask/result. A new photo shows that a mask must be generated. If an exact accepted result for the full current inputs exists, the app verifies and restores it automatically, then shows **Results up to date** and enables export. Otherwise it marks shading/PV results out of date and waits for the existing **Update results** action. The dropdown never silently substitutes another mask if a selected file is missing or invalid.

The application has no general project file today. For this version, “saved into the project” means durable files under `Data/Masks` beside the executable, an active selection in `Data/settings.json`, and a per-photo last-selection map in `Data`. Moving the complete portable application folder preserves them. A scenario export contains the selected mask and its provenance, not every unused variant. If a future project-file feature is introduced, this store can be migrated into it.

## Important behavior to specify

- **Source identity.** Each variant records the SHA-256 of the original sky photo, oriented width/height, lens disk geometry, immutable AI ancestor mask hash, model/resolution, immediate parent variant ID, creation time, label, and edited PNG hash. Editing cannot start without a validated AI-generated ancestor. Only variants matching the current photo content, model, resolution and disk mode are selectable. A changed/replaced photo cannot silently reuse old paint. Model/resolution or disk-mode changes return selection to `AI mask`; previously saved variants remain on disk for their original configuration.
- **Lens and calibration limits.** The brush operates only inside the detected lens disk; outside pixels stay black. The editor shows the disk edge and explains that calibrated camera coverage can limit the effect of white paint. An angular coverage guide is deferred; adjusting an incorrect disk or camera calibration remains a separate workflow.
- **Selection and export truth.** The binary mask currently has a fixed meaning: 255 = open sky and 0 = obstruction/outside lens. The selected variant becomes the active `02-sky-mask/sky-mask.png` for shading and export. The preview label and `mask-details.json` must identify whether it is AI-generated or edited; an additional `mask-provenance.json` records the variant ID and parent/base hashes. The accepted `run.json` records the selected ID and content hash. Export verification checks that exact active mask. The original AI cache and all durable variants remain unchanged.
- **No automatic scientific recomputation.** A new edit or selection without a matching accepted result follows the application's explicit-update rule. It invalidates the shaded result and dependent PV Autonomy result. A previously accepted exact configuration is restored from verified saved output without running inference, weather retrieval or shading again. Irradiance retrieval, solar geometry and unshaded panel transposition remain reusable. A mask-pixel-only change does not alter camera pose, sun-path geometry or cardinal geometry.
- **Concurrent changes and failures.** Saving verifies the source photo/base mask still match the editor's opening snapshot. It writes PNG and metadata to a temporary location, validates both, then publishes the variant atomically. A failed or cancelled save leaves the selected mask and prior result unchanged. External deletion/corruption of a selected variant is an actionable error, not a fallback to AI. An in-flight calculation cannot publish a late result for a previous selection.

## Returning to a previous photo or mask

The current application keeps only one published `Debug Data` dataset. Changing a photo invalidates it and deletes affected artifacts; the existing compute caches do not preserve a complete exportable result for a previous photo. Therefore remembering the mask selection alone cannot make a prior result current again.

Add an **accepted-result vault** under `Data/AcceptedResults`. After each complete update, save an immutable verified snapshot of its `run.json`, registered diagnostic artifacts and UI result data. Key it by all calculation-affecting input identities: sky-photo content, selected mask content/ID, camera profile and pose, site and period, irradiance source content/request, panel settings, numerical options and relevant library versions. Display preferences such as editor opacity and zoom are excluded. Store only complete runs. Share identical artifact blobs by hash where practical so switching masks does not duplicate large unchanged solar/weather workbooks. Show the storage used and provide deliberate cleanup; do not silently evict a result promised for later return.

On selecting a previous photo or mask, look up that exact key. Verify current source hashes and every saved artifact hash, then restore the snapshot through the existing storage lease and bounded staging into the one active `Debug Data` location. Rehydrate the chart, mask preview, overlays and accepted `PanelRun` from the verified saved artifacts; do not invoke the numerical pipeline. Mark the result current and enable export only after the restored manifest passes the same completeness checks as a fresh update. If other current settings differ, retain those settings and require **Update results**; the application does not silently restore older panel, site or period inputs. A cache miss, changed source, changed software version, missing file or failed restore leaves the UI at **Update required**. Switching away and back while work is running uses the existing revision/cancellation guard so no late result can replace the selected one.

PV Autonomy is tied to the exact accepted irradiance result. Preserve its optional `07-battery` scope and settings with the accepted snapshot when present. On return, restore and verify it only if the upstream result identity and PV settings still match; otherwise leave PV at **Evaluate system**. An automatic result restoration is a file/state operation, not an automatic scientific recalculation. If archiving a new result fails, keep its current calculation valid but clearly report that it cannot yet be restored after switching away.

## Source boundaries and planned changes

The secondary window is its own WPF class-library project, `src/MaskEditor/SolarShade.MaskEditor.csproj`, with no reference back to `ApplicationFrontend`, `AppServices`, Debug Data, weather, calibration, shading or PV. The main app references this project and opens its window. The editor receives an immutable full-resolution **EXIF-oriented** photo, an immutable AI-derived starting mask (or a saved revision with its AI ancestor), a lens-disk guide and a suggested label. It returns a validated 0/255 PNG and chosen label through a small save contract. It never chooses the active mask, writes to `Data`, starts a calculation or declares a result current. A host-supplied save callback lets the Save button keep the window open with the paint intact if durable publication fails. The main app verifies source identity, persists the new variant, selects it and updates result state only after that callback succeeds.

| Area | Change | Boundary preserved |
|---|---|---|
| `SkyPhotoMasking` | Add a manual-variant persistence/validation component that accepts a full-resolution binary PNG and base-mask metadata; reuse `SkyMaskExporter` for the active stage. | Leave ONNX inference, thresholds, disk detection and model cache behavior unchanged. |
| `SolarShade.MaskEditor` (new WPF project) | Own the secondary window, editor canvas, brush/undo model, live opacity and zoom controls, and native-pixel coordinate mapping. The immutable original is supplied at full resolution; existing small preview bytes are insufficient. | Reference no frontend orchestration or scientific calculation project. Return edited pixels through a typed contract; never read/write application settings or Debug Data. |
| `ApplicationFrontend` integration | Put **Edit mask** on the preview and the mask dropdown below it. Prepare the editor request, supply the save callback, and handle selection, staleness and result restoration after a successful save. | No paint code in `IrradianceWorkspace`; `ImageOverlayPreview` and its sun-path/cardinal layers stay presentation-only. |
| `UserSettings` and storage | Add `SelectedMaskId` (`null` means current AI mask), a per-photo last-selection map, and durable `Data/Masks/<photo-hash>/<variant-id>/sky-mask.png` plus metadata. Store IDs rather than absolute variant paths so portable relocation works. | Preserve current settings and AI cache; old settings default to AI. |
| `AppServices.PrepareImageStages` | Resolve AI or selected manual variant into the existing `MaskAsset`/`SkyMaskResult` path, validate it, publish the active mask and provenance, then pass the same binary pixels and disk to `PanelSkyScene`. | Do not change shading, transposition, weather or battery numerical APIs. Manual selection bypasses inference; AI remains available. |
| `InputDependencies`, watching and export | Include selected variant ID/content hash in the active-mask key and watched/locked source files. Separate pixel identity from photo/disk/profile geometry so a pixel edit invalidates mask publication, shading and PV while preserving weather, solar, transposition and geometric overlays. Register provenance in the stage manifest and exported snapshot. | Maintain current explicit update, source verification, staging and complete-export rules. |
| Accepted-result vault | Archive only verified complete runs by full calculation identity; restore them into the single current `Debug Data` store after source and artifact verification. Include optional PV output only when its source/settings match. | Preserve the one-current-dataset contract; do not mark a result green based on a mask name or stale in-memory value. |

The existing `SkyMaskExporter` validates 0/255 pixels and dimensions; the new variant validator also checks photo hash, disk geometry, outside-disk black pixels and file hashes. A manual mask can use the existing `SkyMaskResult` as its base metadata with the edited PNG bytes, while separate provenance prevents the exported result from being mistaken for untouched AI output. No downstream scientific library should need an editor-specific branch.

## Implementation sequence

1. Define variant metadata and compatibility rules; implement atomic save/list/load validation and migration from settings without `SelectedMaskId`.
2. Create the standalone `SolarShade.MaskEditor` project and its request/save contract. Build its modal secondary window, binary brush, stroke-level undo/redo, visible zoom/pan controls and live opacity preview. Verify native-pixel alignment on portrait and landscape EXIF-oriented photos.
3. Add the preview button and dropdown. Wire save/select/cancel to the existing revision guard and explicit-update state.
4. Integrate selected-mask resolution and provenance into `02-sky-mask`, dependency keys, file watching, run manifest, export and PV invalidation.
5. Add accepted-result archiving and verified restoration for exact photo/mask/input combinations, including optional PV scope. Make the return path update the UI and export readiness without numerical recomputation.
6. Update Help and usage documentation; package and run the real executable on the bundled example.

## Acceptance checks

- Saving black and white strokes changes only intended native pixels; output remains 0/255 PNG at original dimensions with outside-disk pixels black. Zoom/opacity do not change saved bytes.
- Changing opacity while painting exposes the original photo at every zoom level; the brush continues to target the same native pixels. Slider, wheel and Fit image preserve pointer-to-pixel alignment.
- The editor project can be tested without opening the main application or accessing weather/shading state. Cancel makes no storage or result change; a failed Save leaves the window and unsaved strokes intact. The main app accepts a new variant only through the typed save contract.
- Undo/redo, reset, cancel, save-as-new, restart, portable-folder relocation and multiple variants preserve the expected selection and data.
- Photo A → B → A restores A's last selected mask; it does not accidentally apply B's mask or quietly switch A back to AI.
- Source photo replacement, incompatible geometry, missing/corrupt mask, failed write and late calculation completion cannot produce a falsely current result or silent AI fallback.
- The same selected mask bytes appear in the editor, `02-sky-mask`, the calculation input and the exported scenario; provenance identifies the manual variant. AI and edited selections produce independently reproducible results.
- For a new mask configuration without an accepted snapshot, switching only mask pixels reuses irradiance, solar positions, unshaded transposition and geometric overlays while recomputing shading on explicit Update; PV Autonomy becomes stale until evaluated again. Existing calibration, AI masking, provider, shading, export and battery suites continue to pass.
- Switching photo A → B → A, or edited mask 1 → mask 2 → mask 1, restores a previously accepted result and export readiness when every calculation input and artifact still matches, including after restart and portable-folder relocation. If B changed the site's or panel's settings, returning to A requires **Update results** for those settings. A modified source or corrupt vault artifact produces **Update required**, never a false green state. Matching PV output returns only with matching PV settings.

## Deferred refinements

A remembered editor window size, a calibrated angular-coverage guide, and an explicit command to restore all settings from a prior study could improve this workflow. The current implementation saves each edit as a new immutable variant, automatically selects it, keeps variants in `Data/Masks`, restores previously accepted exact results automatically, requires **Update results** for new configurations, and restricts painting to the detected lens disk.
