AUTOMATIC LIBRARY OUTPUTS

Update results maintains one current dataset in the numbered folders here.
Editing inputs removes affected stale files but never calculates replacements.
Image orientation is prepared during the explicit update, before irradiance.
Calibrate publishes into 01-calibration and saves durable Data/Profiles copies.
This Debug Data folder is beside APPLICATION.exe.

run.json records settings, fingerprints, library/software versions, artifact hashes,
update identity, last successful update time and current status. Unavailable stages
are Skipped; calibration/orientation alone is Partial. Only full calculations can
be Complete. Valid independent files remain if later work fails or is cancelled.
Unchanged files retain their bytes and modification times on subsequent updates.

One sibling Debug Data.staging folder holds unpublished work and is removed when
finished. Interrupted work remains incomplete and can be retried. Debug Data.lock
prevents other instances from writing here at the same time; the empty file may
remain after exit. Close another instance or any locked workbooks before retrying.
Verified historical application run folders are migrated after selected inputs
are copied into Data/Inputs and their saved paths updated. Unrecognized folders,
extra user files, explicit exports and the bundled reference are preserved.

NUMBERED STAGES

01-calibration
  calibration.yml: native lens parameters actually used by the scene.
  camera-profile.json: effective coverage, dimensions and provenance.
  A new calibration also saves observations.json, result.json,
  solver-diagnostics.json, validation.json and existing debug overlays/CSVs.
  A loaded profile is identified as loaded, not recalculated.

02-sky-mask
  sky-mask.png: exact returned black-and-white mask at oriented image size.
    255 = sky; 0 = obstruction or outside lens.
  mask-details.json: model, detected disk, dimensions and execution metadata.

02-orientation
  cardinal-directions-overlay.png: transparent magenta N/E/S/W ticks and labels
    for the original colour photo, generated by the shading library using the
    shared calibration and camera pose. Ticks mark visible bearing-line ends;
    they do not claim that the actual horizon is inside the photograph.
  cardinal-directions.xlsx: numerical marker coordinates and availability.
  cardinal-directions-details.json: camera pose, geometry convention, rendering
    settings and timings. Source photo and binary mask remain unchanged.
  Image/calibration/pose edits invalidate the overlay until Update. Weather/date/panel edits
    reuse it; Show cardinal directions changes visibility only.

03-irradiance
  horizontal-irradiance.xlsx: complete returned/imported source dataset before
    date selection. Includes BHI/DHI in W/m2, source interval IDs and labels,
    source/selected bounds, native cadence, units and provenance.

04-solar-positions
  solar-positions.xlsx: one row at each selected source timestamp.
  solar-integration-samples*.xlsx: exact full-source and selected/clipped
    solar samples, angle conventions, directions and quadrature weights.
    These numerical samples are not additional weather observations.
  sun-path-overlay.png: transparent yellow daily tracks at the native mask size,
    generated from selected apparent solar samples through the shading projector.
    Only available with a compatible calibration and sky image. The binary mask
    remains unchanged; the app's Show sun path control toggles a separate layer.
  sun-path-projection.xlsx: compact rendered vertices with source interval IDs,
    selected sample indices, timestamps and native image coordinates. Additional
    sheets are used when needed. Full solar samples remain in the files above.
  sun-path-details.json: image dimensions, sample counts, projection conventions,
    simplification tolerance, timings and visual line settings. Line thickness
    is an annotation width, not the Sun's physical diameter.

05-transposition
  panel-unshaded.xlsx: direct, sky-diffuse and total received by the inclined
    panel, before obstruction shading. Additional sheets retain DNI inference
    and per-substep direct/isotropic/circumsolar components.

06-shading
  panel-shaded.xlsx: final direct, diffuse and total panel irradiance plus bounds.
  shading-correction-factors.xlsx: shaded/unshaded transmission and loss.
    1 = unchanged, 0 = fully blocked; blank = undefined zero-baseline ratio.
  shading-visibility*.xlsx: receiver-weighted visible/observed fractions.
  panel-results.json: returned interval values, coverage and energy/loss summaries.
  Missing mask/calibration means shading is unavailable; no shaded curve is invented.

Irradiance data determines the time axis: hourly stays hourly, 15-minute stays
15-minute, and explicit variable intervals retain their bounds. Source IDs and
bounds link numerical outputs. Requested coverage gaps fail visibly. Solar
integration does not interpolate or upsample weather. Energy uses actual duration.

Large detail outputs are divided into numbered files or additional worksheets;
read all parts. Reused artifacts are identified in run.json and remain unchanged.
The owning libraries save these scientific artifacts from their return values;
the frontend only sequences the calls and records run status.

Export results copies a complete successful run to a new scenario folder.
Example/Irradiance holds the bundled input workbook. Example/Debug Data/reference-run
holds a fixed library-generated example. Current outputs are saved here.
Keep Data/Profiles and Data/Inputs when moving or backing up the application.
